> - v1: KiCad .sch 텍스트와 데이터시트 기반 1차 분석.

## 1. 회로도의 부품 현황

회로도(schematic.kicad_sch) 부품:
- U1, U2, U4, U5: MCP4161 디지팟 (4개)
- U3: ESP32-WROOM-32E (bare 모듈 심볼)
- U6: 74HCT245
- Q3: 2N7000 MOSFET
- D1, D2: 1N5817 다이오드
- R1, R2: 470Ω
- R5, R6: 10kΩ
- C1, C2, C3, C4: 0.1µF
- SW1: 페어링 스위치
- JS1: Apple II 조이스틱 커넥터

## 2. ESP32-WROOM-32E — 🚨 Critical 이슈

### 2.1 🛑 **CRITICAL: VDD33 핀이 어떤 와이어에도 연결되지 않음 (floating)**

**검증 방법**: .sch 파일에서 ESP32 심볼 위치 (50.8, 69.85), VDD 핀(pin 2)의 절대 좌표 (50.8, 34.29)에 와이어가 존재하는지 직접 검색 → **연결 와이어 0개**.

PDF 회로도에서는 VDD 핀 위로 짧은 선이 보이지만, 이는 KiCad 라이브러리 심볼의 핀 그래픽(stub)이며 전기적 연결이 아닙니다. ERC를 실행하면 "unconnected power input" 오류가 발생할 것입니다.

- **누락 결과**: 본 회로도대로 bare 모듈을 조립하면 ESP32 칩에 전원이 공급되지 않아 **부팅 자체가 불가능**.
- **암묵적 가정**: ESP32 개발보드를 사용하여 USB로 전원이 공급되는 것을 전제로 함.

### 2.2 🛑 **CRITICAL: EN(CHIP_PU) 핀이 어떤 와이어에도 연결되지 않음 (floating)**

**검증 방법**: EN(pin 3)의 절대 좌표 (35.56, 39.37)에 와이어 존재 여부 검색 → **연결 와이어 0개**.

**데이터시트 §4.6 인용:**
> "It is advised to add an RC delay circuit at the EN pin. The recommended setting for the RC delay circuit is usually R = 10 kΩ and C = 1 µF."

- **누락 부품**: 10kΩ 풀업 + 1µF 캐패시터.
- **누락 결과**: EN이 floating이면 칩의 활성화/비활성화가 불안정 (내부 약한 풀업이 있더라도). 잡음에 의해 의도치 않게 RESET 발생 가능.
- **암묵적 가정**: 개발보드 내부에 EN 풀업/리셋 회로가 포함됨.

### 2.3 ⛔ 필수: 3.3V 전원 공급원
**데이터시트 §6.2 Recommended Operating Conditions:** VDD = 3.0V ~ 3.6V (typical 3.3V).

- **회로도 상태**: 회로도 전체에 **3.3V 레귤레이터 또는 3.3V 네트가 존재하지 않음**. JS1을 통해 들어오는 5V만 존재.
- **누락 부품**: 5V → 3.3V LDO (예: AMS1117-3.3) + 입출력 캐패시터.
- **암묵적 가정**: 개발보드의 USB 입력 + 내장 3.3V LDO 사용.

### 2.4 ⛔ 필수: VDD33 디커플링 캐패시터
**데이터시트 §9 Reference Schematic:** 모듈 VDD 핀 부근에 C20=1µF 명시.

- **회로도 상태**: ESP32 VDD 핀 자체가 floating이므로 디커플링 캐패시터도 당연히 없음.
- **누락 부품**: 10µF + 0.1µF (병렬).

### 2.5 ⚠️ 권장: 스트래핑 핀(Strapping Pins) 처리
**데이터시트 §4 Table 4 Default Configuration of Strapping Pins:**

| 핀 | 기능 | 모듈 내부 기본 | 본 프로젝트 사용처 |
|---|---|---|---|
| GPIO0 | Boot mode | Pull-up (1) | 미사용 — NC |
| GPIO2 | Boot mode | Pull-down (0) | 미사용 — NC |
| GPIO5 | SDIO timing | Pull-up | **PIN_U2_CS로 사용** |
| GPIO12 (MTDI) | VDD_SDIO voltage select | Pull-down | 미사용 — NC |
| GPIO15 (MTDO) | U0TXD enable | Pull-up | 미사용 — NC |

- **회로도 상태**: 모든 스트래핑 핀이 외부 회로 없이 NC. 모듈 내부의 약한 풀업/풀다운에만 의존.
- **GPIO12(MTDI)** 가 power-up 시 LOW여야 내장 LDO가 3.3V로 동작. 모듈 내부 weak pull-down으로 일단 OK지만, 노이즈에 취약. 외부 풀다운 권장.

### 2.6 ⚠️ 권장: 리셋 / 부트 버튼
**데이터시트 §4.6, Figure 6 Power-up and Reset Timing.**

- 회로도에 EN 리셋 버튼 없음, GPIO0 부트 버튼도 없음.
- **암묵적 가정**: 개발보드 제공.

### 2.7 ⚠️ 권장: USB-to-Serial 회로
- 펌웨어 다운로드용 회로 없음.
- **암묵적 가정**: 개발보드 제공.

### 2.8 결론: ESP32 부분은 "개발보드 사용 전제"의 회로도
회로도가 **bare ESP32-WROOM-32E 모듈 심볼**(`RF_Module:ESP32-WROOM-32E`)을 사용하면서도, 모듈을 직접 구동하는 데 필요한 최소 부품(3.3V 레귤레이터, EN RC, 디커플링)이 전혀 없습니다. 개발보드 심볼(예: `RF_Module:ESP32-DevKitC-32`)로 바꾸면 이 문제들이 자연히 해소됩니다.

## 3. MCP4161 디지팟

> 데이터시트 §8.4.1 *Power Supply Considerations*.

### 3.1 ✅ VDD 디커플링 (4개 모두 충족)
**데이터시트 인용:**
> "The recommended bypass capacitor value is 0.1 µF. This capacitor should be placed as close as possible to the power pin."

- **회로도 상태**: C1, C2, C3, C4 (각 0.1µF)가 U1, U2, U4, U5 옆에 1:1로 배치됨. PDF에서 시각적으로 확인됨. ✅

### 3.2 ℹ️ 8핀 패키지 — SHDN/WP 핀 없음, 추가 처리 불필요

### 3.3 ⚠️ 권장: SDI/SDO 라인 풀업
- 8핀 MCP4161은 SDI/SDO 핀이 멀티플렉싱됨 (open-drain 출력).
- 본 프로젝트는 디지팟에서 읽지 않으므로 단방향(SDI만) 사용. SDO 풀업 불필요. ✅

## 4. SN74HCT245 — 부분적 누락

> 데이터시트 §10 *Power Supply Recommendations*, §11 *Layout Guidelines*.

### 4.1 ⛔ 필수: VCC 디커플링 캐패시터 (누락)
**데이터시트 인용:**
> "Each VCC pin **must** have a good bypass capacitor... A 0.1 µF and a 1 µF are commonly used in parallel."

- **검증**: U6 VCC(pin 20) 절대 좌표 (109.22, 57.15)에서 (109.22, 22.86)으로 가는 와이어만 존재. 캐패시터 부품이 이 라인에 매달려 있지 않음.
- **회로도 상태**: U6 VCC에 전용 디커플링 캐패시터 **없음**.
- **누락 부품**: 0.1µF + 1µF (병렬).

### 4.2 ✅ DIR 핀 — GND에 올바르게 결선됨 (v1 정정)
**v1 분석에서 PDF 시각 판독으로 DIR이 VCC에 묶였을 가능성을 제기했으나, .sch 와이어를 직접 추적한 결과 정정합니다.**

**검증**: 
- U6 DIR(pin 1) 절대 좌표 (121.92, 87.63)
- 와이어 (121.92, 87.63) → (132.08, 87.63) → (132.08, 128.27) — y=128.27은 GND 레일
- 따라서 DIR = LOW = **B→A 방향** (ESP32 → 디지팟). 코드 동작과 일치. ✅

KiCad 라이브러리 심볼의 핀 이름이 "A->B"로 적혀 있어 PDF에서 혼동을 유발하나, 실제 결선은 정확합니다.

### 4.3 ✅ 부동 입력 없음
- B0~B7(pins 11-18) 8개 채널이 SCK, MOSI, 4×CS, BTN0, BTN1로 모두 사용됨.
- A0~A7(pins 2-9) 모두 디지팟 또는 버튼 회로에 연결됨.

### 4.4 ✅ HCT 입력 임계값 호환
- ESP32 3.3V 출력이 HCT의 TTL 임계값(VIH ≥ 2.0V @ VCC=5V)을 만족.

## 5. 2N7000 MOSFET — 모든 보호 회로가 존재 (v1 정정)

> 데이터시트 *ON Characteristics*.

### 5.1 ✅ Q3 게이트 풀다운(R5) — 회로도에 존재 (v1 정정)
**v1 분석에서 "게이트 풀다운 누락"을 지적했으나, .sch 와이어를 추적한 결과 정정합니다.**

**검증**:
- Q3 Gate(pin 2) 절대 좌표 (80.01, 104.14)
- 와이어 (80.01, 104.14) ← (72.39, 104.14) ← (72.39, 111.76) = R5 위쪽 단자
- R5 (10kΩ) → (72.39, 119.38) → (72.39, 128.27) = GND 레일
- **R5는 Q3 게이트와 GND 사이에 정확히 풀다운으로 배치됨.** ✅

ESP32가 부팅 중 IO27이 floating일 때, R5가 게이트를 GND로 끌어내려 MOSFET이 OFF 상태 유지 → OE가 R6 풀업으로 HIGH → 74HCT245 high-Z. 페일세이프가 의도대로 동작합니다.

### 5.2 ✅ OE 풀업 저항(R6) — 정상
**검증**:
- 74HCT245 OE(pin 19) 절대 좌표 (121.92, 90.17)
- OE → (121.92, 99.06) → 좌측으로 Q3 Drain(87.63, 99.06), 우측 R6 상단 (120.65, 110.49)
- R6 하단 (120.65, 118.11) → (120.65, 140.97) → (198.12, 140.97) → JS1 +5V (205.74, 140.97)
- **R6는 OE와 +5V 사이의 풀업으로 정확히 배치됨.** ✅

### 5.3 ⚠️ 알려진 한계: 게이트 임계 전압
**데이터시트 인용:**
> VGS(th) typical 2.1V, **max 3.0V** @ VDS=VGS, ID=1mA

- ESP32 GPIO 3.3V로 max 3.0V 임계값을 구동하므로 마진이 0.3V뿐.
- README가 이미 명시적으로 인정한 사항. 동작은 하지만 로직 레벨 MOSFET(BSS138, AO3400 등) 교체 권장.

### 5.4 ℹ️ 게이트 직렬 저항 없음
- 100~470Ω 정도의 게이트 시리즈 저항이 없으나, 저속 스위칭이라 동작에 영향 미미.

## 7. 시각 검증 후 추가 발견 사항

PDF와 .sch 와이어 추적을 통해 v1에서 미검출했던 사항:

### 7.1 전원 네트가 라벨 없이 와이어만으로 연결됨
- y=22.86 horizontal rail = **+5V 레일** (JS1 pin 2에서 출발, 모든 디지팟 VDD와 74HCT245 VCC로 분배)
- y=128.27 horizontal rail = **GND 레일** (ESP32 GND, 74HCT245 GND, 모든 디지팟 VSS, 페어링 SW1, R5, JS1 GND로 분배)
- KiCad의 `power:` 라이브러리 심볼(예: VCC, GND, +5V)이 **전혀 사용되지 않음**. → ERC 약화, 가독성 저하.

### 7.2 1kΩ SPI 시리즈 저항 6개 — 회로도에 없음
- README에 "1kΩ 6개" 명시되어 있으나 회로도에는 R1, R2(470Ω), R5, R6(10kΩ) 4개만 존재.
- ESP32 ↔ 74HCT245 신호선에 시리즈 저항이 없는 상태로 직접 연결.

### 7.3 GPIO 핀 할당 — 검증 완료
.sch 와이어 추적으로 확인된 ESP32 GPIO 사용:
- GPIO13(IO13) ↔ SW1 (PAIRING) — 코드 PIN_PAIR=13 ✅
- GPIO27(IO27) ↔ Q3 Gate (OE 제어) — 코드 PIN_245_OE=27 ✅
- 나머지 6개 (4×CS, SCK, MOSI) 및 2개 (BTN0, BTN1)는 74HCT245의 B0~B7로 들어감 — 핀별 대응은 KiCad GUI에서 시각적으로 마무리 확인 권장.

## 9. 결론 (v2 종합)

### 9.1 v1 대비 정정 사항
1. **74HCT245 DIR**: VCC 직결 의심 → **GND에 올바르게 결선됨**으로 정정.
2. **Q3 게이트 풀다운**: 누락 → **R5(10kΩ)가 이 역할 수행**으로 정정. 페일세이프 회로는 완성도 있게 설계됨.

### 9.2 새로 확인된 Critical 이슈
1. **ESP32 VDD33 핀이 어떤 와이어에도 연결되지 않음** (회로도상 floating). 
2. **ESP32 EN 핀도 floating**.
3. 결과적으로 본 회로도를 bare 모듈로 그대로 조립하면 **칩이 동작하지 않음**.

### 9.3 회로도 보완 권장
**전제**: 최종 설계는 **bare ESP32-WROOM-32E 모듈**을 사용합니다. 개발보드는 펌웨어 디버깅/플래시 용도로만 별도 사용하고, 회로도에는 반영하지 않습니다. 따라서 회로도는 데이터시트 reference design의 최소 회로를 모두 포함해야 합니다.

**우선순위 1 (모듈 동작에 반드시 필요)**:
1. **3.3V LDO 추가** (5V → 3.3V).
2. **EN RC 리셋 회로**: 10kΩ 풀업 + 1µF 캐패시터.
3. **VDD33 디커플링**: 10µF + 0.1µF.
4. **GPIO12 외부 풀다운** (10kΩ to GND) — 부트 시 LDO 전압 모드 확정.
5. **74HCT245 VCC 디커플링**: 0.1µF + 1µF 병렬.

**우선순위 2 (개발/디버깅 편의)**:
6. **프로그래밍 헤더** (6-pin: GND, 3V3, EN, IO0, RXD0, TXD0) — 외부 USB-Serial 어댑터(FTDI 등) 또는 개발보드를 일시 연결해 펌웨어 다운로드.
7. **EN 리셋 버튼**, **IO0 부트 버튼** — 펌웨어 다운로드 모드 진입.
8. **GPIO0 풀업** (10kΩ to 3V3) — 평상시 SPI Boot Mode 유지.

**우선순위 3 (안정성/일관성)**:
9. README의 "1kΩ 6개"가 어디에 쓰이는지 회로도에 명시 (SPI 시리즈 보호 저항 추정).
10. 회로도에 표시되지 않은 0.1µF 캐패시터들을 모두 그려 넣어 재현성 확보.

**우선순위 4 (가독성)**:
11. KiCad의 `power:` 심볼(VCC, GND, +5V, +3V3)로 전원 네트 명시.
12. 신호 네트 라벨(`SCK`, `MOSI`, `CS_U1`~`CS_U4`, `OE`, `BTN0`, `BTN1` 등) 부여.
13. KiCad GUI에서 **ERC** 실행 — VDD/EN floating 등 critical 이슈 자동 검출.

### 9.4 현재 회로도가 (개발보드와 함께) 동작하는 이유
- 현재 회로도에 누락된 ESP32 최소 구동 회로(LDO, EN RC, VDD 디커플링 등)가 **사용 중인 개발보드 내부에 이미 존재**하기 때문.
- 그러나 최종 목표가 bare 모듈이라면, 회로도가 그 모든 부품을 명시적으로 포함해야 PCB 제작이나 영구 빌드가 가능합니다.

## 10. 회로도 수정 가이드 (KiCad GUI에서 작업)

### 10.0 작업 전제

- **최종 설계 = bare ESP32-WROOM-32E 모듈** (개발보드는 펌웨어 디버깅/플래시용으로만 별도 사용, 회로도엔 포함시키지 않음).
- **전원은 Apple II 게임포트 5V(JS1 pin 2) 단일 입력**. bare 모듈은 USB가 없고, 외부 USB/DC 입력도 추가하지 않음. 따라서 디지팟·74HCT245·ESP32 LDO 모두 같은 5V 레일에서 전원을 공급받음.
- **펌웨어 업데이트는 UART**: J2 프로그래밍 헤더(§10.1.5)에 외부 USB-Serial 어댑터(FTDI 등)를 연결해 펌웨어를 다운로드. ESP32 자체에는 USB-Serial 회로를 두지 않음.
- ESP32를 동작시키는 데 필요한 **모든 외부 부품을 회로도에 추가**해야 합니다.

#### ⚠️ 전원 예산(Power Budget) 고려사항

| 부하 | 전류 |
|---|---|
| ESP32 idle | ~80 mA |
| ESP32 Bluetooth 송신 peak (Classic/BLE 공용) | ~150 mA (Classic 기준, 수 ms pulse) / ~80~100 mA (BLE) |
| ESP32 Wi-Fi peak (참고, 사용 안 함) | ~300~500 mA |
| 디지팟 4개 + 74HCT245 + 풀업 | < 10 mA |
| **합계 (BT 사용 시)** | **정상 ~100 mA, peak ~200 mA** |

- Apple IIGS / Laser 128 게임포트 5V는 보통 최대 수백 mA를 견딜 수 있으나 **모델·연식에 따라 다름**.
- 본 프로젝트는 **Bluetooth Classic + BLE 공용**(Bluepad32가 둘 다 지원하며 컨트롤러에 따라 자동 선택)이지만, Wi-Fi가 꺼져 있어 피크 전류가 비교적 낮아 게임포트로 충분할 가능성이 높습니다. Classic이 BLE보다 peak가 큰 편이므로 캐패시터 산정은 Classic 기준(~150mA)으로 합니다.

#### Wi-Fi 비활성 상태 검증

회로도/하드웨어 가정의 핵심은 "Wi-Fi가 동작하지 않는다"는 점입니다. 코드와 라이브러리를 직접 점검한 결과:

1. **펌웨어 코드** ([appleii-bluetooth-joystick.ino](../appleii-bluetooth-joystick.ino)):
   - `#include <WiFi.h>` 없음. include는 `math.h`, `Bluepad32.h`, `SPI.h`, `Preferences.h`뿐.
   - `WiFi.*()` / `esp_wifi_*()` 호출 0개.
2. **Bluepad32 라이브러리** (ricardoquesada/bluepad32, main 브랜치):
   - 라이브러리 소스 전체에서 `esp_wifi_init` / `WiFi.h` 호출 0개.
   - `BP32.setup()`은 Bluetooth 스택(BR/EDR + BLE)만 초기화하며 Wi-Fi 라디오는 건드리지 않음.
   - CHANGELOG v0.2.0: "Software controls WiFi/Bluetooth coexistence: disabled" — 빌드 단에서 SW 코엑시스턴스 자체가 꺼져 있음.
3. **ESP32 기본 동작** (Espressif Arduino-ESP32):
   - Wi-Fi 드라이버는 사용자가 `WiFi.begin()`, `WiFi.mode()`, `WiFi.softAP()` 등을 명시적으로 호출하기 전까지 **OFF** 상태.
   - 자동 시작 없음.

→ 결론: **Wi-Fi 라디오는 부팅부터 종료까지 활성화되지 않음.** 전원 예산은 BT 송수신 전류만 고려하면 됩니다 (~150mA peak, Classic 기준).

> **만약 향후 펌웨어에 Wi-Fi 기능을 추가하면**, 위 가정이 깨져 피크 전류가 300~500mA로 치솟습니다. 이 경우 회로 자체를 다시 검토해야 하며 (LDO 정격, 입력 캐패시터, Apple II 게임포트 부하 한계), 본 회로도 그대로는 부족할 가능성이 큽니다.
- **핵심 대책**: LDO 입력측 벌크 캐패시터를 충분히 크게(220~470µF) 두어 BT 송신 시 순간 전류를 흡수. 이로 인해 Apple II 측 5V 라인의 ripple을 최소화.
- 보호 차원에서 입력 라인에 폴리퓨즈(예: 500mA, `Polyfuse`/`Resettable_Fuse` 심볼) 추가 권장 (선택). 게임포트 5V 단락 시 Apple II 보호.

### 10.1 ESP32 모듈 최소 구동 회로

#### 10.1.1 3.3V LDO 레귤레이터 (Apple II 5V → 3.3V)

| 항목 | 값 |
|---|---|
| 심볼 | `Regulator_Linear:AMS1117-3.3` |
| Reference | U7 |
| Footprint | `Package_TO_SOT_223:SOT-223-3_TabPin2` (SMD) 또는 `Package_TO_SOT_THT:TO-220-3_Vertical` (LD1117 THT 사용 시) |
| Value | `AMS1117-3.3` |

**결선**:
- Pin 1 (GND) → GND 레일
- Pin 3 (VI, 입력) → **기존 +5V 레일** (JS1 pin 2와 동일한 net; 회로도의 y=22.86 라인)
- Pin 2 (VO, 출력) → 새로운 `+3V3` 네트

**LDO 입출력 캐패시터** (BT 전류 spike 흡수를 위해 입력측 bulk를 크게):
| 부품 | Value | Footprint | 위치 | 목적 |
|---|---|---|---|---|
| C5 (입력 bulk) | `220µF` 또는 `470µF` 전해 (16V) | `Capacitor_THT:CP_Radial_D8.0mm_P3.50mm` | U7 VI 핀 근접 | BT 송신 시 순간 전류를 로컬에서 공급해 Apple II 5V 라인 ripple 억제 |
| C6 (입력 디커플) | `0.1µF` 세라믹 | `Capacitor_THT:C_Disc_D5.0mm_W2.5mm_P5.00mm` | U7 VI 핀 근접 | 고주파 노이즈 필터 |
| C7 (출력 bulk) | `22µF` 탄탈 또는 전해 | `Capacitor_THT:CP_Radial_D5.0mm_P2.50mm` | U7 VO 핀 근접 | AMS1117 datasheet 안정성 권장 |
| C8 (출력 디커플) | `0.1µF` 세라믹 | 디스크형 | U7 VO 핀 근접 | 고주파 노이즈 |

> **벌크 캐패시터 크기 산정**: Bluetooth Classic 송신 pulse(BLE보다 worst-case)가 ~150mA × 5ms 정도 ≈ 0.75mC. 100µF 캐패시터의 1V drop = 100µF × 1V = 100µC ≪ 0.75mC. 따라서 **220µF 이상** 권장. 부족하면 ESP32가 브라운아웃으로 리부트할 수 있음. BLE만 쓸 경우엔 100µF로도 가능하나, Classic 호환을 유지하려면 220µF 이상을 두는 게 안전.

**(선택) 입력 보호 폴리퓨즈**:
| 부품 | Value | 위치 | 목적 |
|---|---|---|---|
| F1 | `500mA` 폴리퓨즈 (`Device:Polyfuse`) | JS1 +5V ↔ +5V 레일 사이 직렬 | 단락 시 Apple II 보호 |

#### 10.1.5 펌웨어 프로그래밍 헤더 (UART)

bare 모듈에는 USB가 없으므로 **외부 USB-Serial 어댑터(FTDI 232RL, CP2102, CH340 등) 또는 개발보드의 UART 핀을 임시 연결**해 펌웨어를 다운로드. ESP32 자체 UART0(IO1=TXD0, IO3=RXD0)을 이 헤더로 노출.

| 항목 | 값 |
|---|---|
| 심볼 | `Connector_Generic:Conn_01x06` |
| Reference | J2 |
| Footprint | `Connector_PinHeader_2.54mm:PinHeader_1x06_P2.54mm_Vertical` |
| Value | `UART_PROG` |

**핀 매핑** (FTDI 6-pin 케이블 핀아웃과 호환):
| 헤더 핀 | 신호 | 연결 | 비고 |
|---|---|---|---|
| 1 | GND | GND 레일 | 어댑터 GND와 공통화 (필수) |
| 2 | 3V3 (또는 NC) | NC 권장 | 어댑터에서 3V3 공급하지 않음 (회로는 Apple II 5V로 자체 동작) |
| 3 | EN | ESP32 EN (pin 3) | 어댑터 DTR로 자동 리셋 가능 |
| 4 | IO0 | ESP32 IO0 (pin 25) | 어댑터 RTS로 자동 부트모드 진입 가능 |
| 5 | RXD0 | ESP32 IO3 (pin 34, U0RXD) | 어댑터 TX → ESP32 RX |
| 6 | TXD0 | ESP32 IO1 (pin 35, U0TXD) | ESP32 TX → 어댑터 RX |

> **운용 시나리오**:
> - Apple II 전원 켠 상태에서 J2에 FTDI 케이블 연결 → `esptool.py` 또는 Arduino IDE로 펌웨어 업로드.
> - 또는 보드만 따로 5V 외부 공급(JS1 핀에 직접 5V 인가)하고 J2로 업로드도 가능.
> - 자동 리셋/부트 회로(RTS/DTR → 2N7000 2개)도 추가 가능하나 복잡. **버튼 수동 조작이 가장 단순**.

|---|---|---|---|---|
| SW2 | `Switch:SW_Push` | `RESET` | `Button_Switch_THT:SW_PUSH_6mm` | ESP32 EN ──SW2── GND |

### 10.4 1kΩ SPI 시리즈 보호 저항 6개

README의 "1kΩ × 6"이 SPI 신호 보호용이라고 가정. ESP32와 74HCT245 사이의 long trace ringing/EMI를 억제하고, GPIO를 사고로부터 보호.

**추가 부품**: 6개 모두 `Device:R_US`, Value `1KΩ`, Footprint `Resistor_THT:R_Axial_DIN0207_L6.3mm_D2.5mm_P10.16mm_Horizontal`.

| Reference | 신호 | 결선 |
|---|---|---|
| R10 | CS_U1 | ESP32 IO4 ── R10 ── 74HCT245 B0 (pin 18) |
| R11 | CS_U2 | ESP32 IO5 ── R11 ── 74HCT245 B1 (pin 17) |
| R12 | CS_U3 | ESP32 IO25 ── R12 ── 74HCT245 B2 (pin 16) |
| R13 | CS_U4 | ESP32 IO26 ── R13 ── 74HCT245 B3 (pin 15) |

| R15 | MOSI | ESP32 IO23 ── R15 ── 74HCT245 B5 (pin 13) |

> 어디에 어느 저항을 넣는지는 원 저작자(kirbyfrugia) 의도에 따라 다를 수 있음. 위는 SPI 6개 신호선에 모두 거는 해석. 버튼 신호(BTN0/BTN1)에는 이미 470Ω(R1, R2)이 있으므로 추가 안 함.

**KiCad 작업**: 와이어를 끊고 그 사이에 저항을 삽입. 와이어 끊기는 `Edit → Break Wire` 또는 와이어 끝점을 잡아 끌어 분리.

### 10.5 `power:` 심볼로 전원 네트 명시

**현재 상태**: 와이어 직접 연결로만 +5V/GND 분배. KiCad의 ERC가 power input pin들을 제대로 인식하지 못함.

**작업**:
1. `Place → Add Power Port`로 다음 심볼들을 적절한 위치에 배치:
   - `power:+5V` — JS1 pin 2 출구, 모든 디지팟 VDD, 74HCT245 VCC, LDO 입력 측
   - `power:+3V3` — LDO 출력, ESP32 VDD33, R7(EN 풀업) 상단, R8(IO0 풀업) 상단, 프로그래밍 헤더 3V3
   - `power:GND` — 모든 IC GND 핀, JS1 pin 3, 저항/캐패시터 GND 단자
2. 기존 와이어들을 power 심볼 핀에 연결.
3. 같은 이름의 power 심볼들은 KiCad가 자동으로 같은 네트로 처리.

**이점**: ERC가 floating power input을 자동 검출. 신호 라우팅이 깔끔해짐.

### 10.9 수정 후 검증 절차

1. **ERC (Electrical Rules Check) 실행**: `Inspect → Electrical Rules Checker → Run`
   - "Unconnected" 또는 "Floating power input" 오류가 없어야 함.
   - 의도적인 NC 핀이 있다면 `Place → Add No Connection Flag`로 표시.

2. **시각 검증**:
   - `File → Plot → PDF`로 PDF 재생성.
   - 모든 IC의 전원, GND, 디커플링 캐패시터가 잘 그려졌는지 확인.

3. **풋프린트 일치 확인**: `Tools → Footprint Assignment Tool` (CvPcb)로 BOM과 실제 부품 footprint를 다시 매칭.

4. **본 분석 문서 업데이트**: 수정 완료 후 본 문서의 §2~§4 누락 항목 ❌ → ✅ 로 갱신.
